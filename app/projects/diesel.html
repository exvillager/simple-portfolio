> How I Built My Own Web Framework in Bun

Around June or July 2024, I was making the same repetitive APIs in Express and began wondering how these frameworks actually work under the hood. So I thought, why not build my own lightweight library like Express/Hono from scratch to understand the internals?

That is how Diesel.js started.

1. Route Registration & Storage

Initially, I started by implementing standard HTTP helper methods like .get(), .post(), and .delete(). When a user defines a route: 

app.get("/user", userHandler);

The framework needs to store these route mappings somewhere internally so incoming client requests can be dispatched to the right handler. For the initial version, I used a simple dictionary map: 

diesel.routes[method + path] = handler;

2. Handling Incoming Requests

When an HTTP request hits the server via Bun.serve, the framework parses the URL path (e.g. http://localhost:3000/user → /user), looks up the matching handler from the route table, and invokes it with Bun's native Request object: 

const matchedHandler = diesel.routes[req.method + path];
if (matchedHandler) {
  return matchedHandler(req);
}

After building this first prototype, the core request-response cycle of frameworks like Express and Fastify became much clearer. But the framework still lacked two critical features: middleware pipelines and dynamic route matching.

3. Adding Middleware Support

Middleware functions are simply hooks that execute before the main route handler. In Diesel, I broke middleware down into two types:

  • Global Middleware: A list of middleware functions that execute on every incoming request, regardless of whether a route handler matches.
  • Route-Specific Middleware: Middleware that only runs for specific route paths (e.g., authentication on /user).
app.useMiddleware("/user", (req) => {
  console.log("Running route-specific middleware on /user");
});

To implement this:

  • Stored global middlewares in an array ([]).
  • Stored route-specific middlewares in a Map keyed by route path.
  • In handleRequest, iterate and execute all global middlewares first, then retrieve and execute route-specific middlewares via diesel.routeMiddleware(path), and finally call the route handler.

4. Upgrading to a Trie-Based Router

A plain JavaScript object works for exact static routes like /user/login, but completely breaks down when handling:

  • Dynamic route parameters: /user/:id (where :id can be any value).
  • Wildcard routes: /assets/* (matching any nested path).

To solve this, I designed and built a custom Trie-based HTTP router capable of fast prefix matching, parameter extraction, and wildcard handling.
